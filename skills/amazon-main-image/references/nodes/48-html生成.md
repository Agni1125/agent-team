# 四、單一核心主軸規則

Hero 區塊必須包含「一句話策略總結」。

一句話策略總結只回答一件事：
這套主輔圖圍繞什麼核心主軸進行說明？

一句話必須包含：
1. 一個明確的核心主軸
2. 若資料足夠，可補充 2 到 4 個支撐角度

核心主軸只能有一個，不得把多個賣點並列成多個主軸。

正確結構：
「本組主輔圖圍繞【單一核心主軸】進行說明，並透過【支撐角度 1】、【支撐角度 2】、【支撐角度 3】支撐購買決策。」

錯誤結構：
「本組主輔圖主要用來強化【賣點 1】、【賣點 2】、【賣點 3】與【賣點 4】。」

Hero 區塊必須能對應後面的六大核心結論。
六大核心結論中的每一點，都必須說明它如何支撐 Hero 的單一核心主軸。

# 五、核心結論區塊規則

核心結論區塊不是六個平行摘要，而是一條由資料分析推導到圖片策略的決策鏈。

核心結論必須固定拆成 6 個小主題卡片，且順序不得調換：

1. 產品事實與溝通邊界
2. 核心購買需求
3. 購買疑慮與信任缺口
4. 競品溝通現狀與差異化機會
5. 宣稱風險與設計限制
6. 主輔圖溝通路徑總結

六張卡片的邏輯關係如下：

第 1 項：產品事實與溝通邊界
- 用來確認產品事實、產品規格、可使用賣點與不可違反的限制
- 它是整份報告的事實底座
- 不得編造產品功能、規格、認證、效果或限制

第 2 項：核心購買需求
- 用來判斷買家為什麼需要這個產品
- 必須從搜尋、社群、Persona、評論、競品或產品資料中提取需求訊號
- 它決定主輔圖應優先處理哪個需求，而不是堆砌功能

第 3 項：購買疑慮與信任缺口
- 用來判斷買家購買前還有哪些疑慮
- 可包含效果疑慮、使用方式疑慮、材質疑慮、尺寸疑慮、氣味疑慮、相容性疑慮、耐用性疑慮、信任不足等
- 它決定哪些輔圖需要負責解疑

第 4 項：競品溝通現狀與差異化機會
- 用來判斷競品已經在講什麼，以及我方圖片可以從哪裡切入差異化
- 必須說明哪些內容已經飽和，哪些內容仍有補強空間
- 它決定我方圖片不能只是複製競品，而要找到更有轉化價值的溝通角度

第 5 項：宣稱風險與設計限制
- 用來確認圖片文案、畫面、賣點表達不能越過哪些邊界
- 可包含合規風險、功效宣稱風險、醫療化語言風險、絕對化語言風險、樣本數據誤用風險、產品外觀失真風險、錯誤來源資料套用風險
- 它必須放在策略總結之前，作為形成圖片策略前的限制條件

第 6 項：主輔圖溝通路徑總結
- 這是前 1 到 5 項推導後形成的策略結果
- 不得寫成資料來源摘要
- 不得寫成「圖片策略架構指出」「根據圖片策略架構」
- 必須總結整組主輔圖應採用的溝通順序與購買決策路徑

第 6 項必須回答：
1. 前五項分析共同推導出什麼圖片策略方向
2. 整組主輔圖應該如何從產品識別走到購買理由
3. 每張圖之間如何承接，而不是各自獨立展示賣點
4. 這條溝通路徑如何支撐 Hero 中的單一核心主軸

每個小主題卡片都必須包含：
1. 小主題標題
2. 資料依據
3. 策略解讀
4. 設計執行方向
5. 2 到 4 個數據支持小標籤
6. 支持強度
7. 與 Hero 一句話策略總結的關聯

標題必須使用：
- 資料依據
- 策略解讀
- 設計執行方向

禁止使用：
- 客觀觀察
- 圖片行動
- 為什麼這張圖放在第幾張

# 六、搜尋與社群內容分析使用規則

「搜尋與社群內容分析」不是原始搜尋資料，也不是普通補充資料，而是前置節點已整理完成的「消費者 Persona 與內容策略分析結果」。

此區塊可能已包含：

1. 資料品質診斷
   - 執行狀態
   - 是否可生成 Persona
   - 來源診斷
   - 產品主題診斷
   - 資料限制
   - 無效來源提醒

2. 四種來源的獨立分析結果
   - Google 搜尋意圖分析
   - Reddit 社群評論分析
   - YouTube Shorts Search 內容搜尋分析
   - YouTube Comments 留言樣本分析

3. 跨來源合併後的 Persona 與內容策略結果
   - 消費者需求分群
   - 跨來源需求訊號
   - Persona
   - 各 Persona 的內容策略
   - 跨 Persona 洞察
   - 需避免的宣稱風險
   - 上游資料不足或資料錯配提醒

4. 可量化數據
   - 關鍵字提及次數
   - 樣本總數
   - 留言樣本數
   - 樣本內提及比例
   - 關鍵字頻率
   - 高互動留言主題
   - 分析影片數
   - 分析留言數
   - views_reference 或 views 作為內容熱度參考

5. 證據強度
   - strong
   - medium
   - weak
   - insufficient

本報告必須優先從此區塊提取以下內容：
1. 買家搜尋階段需求
2. 購買前疑問
3. 真實使用痛點
4. 購買疑慮與信任缺口
5. 消費者自然語言
6. 短影音內容 Hook
7. YouTube 留言主題與樣本內提及比例
8. Persona 分群依據
9. Listing 圖片策略啟示
10. 文案語氣與內容角度
11. 需要補強的證據
12. 需要避免的誇大宣稱

如果此區塊已提供 Persona 合成結果，報告中的「核心購買需求」「購買疑慮與信任缺口」「主輔圖溝通路徑總結」必須優先參考其中的：
- 跨來源需求訊號
- Persona
- 各 Persona 的內容策略
- 跨 Persona 洞察
- 證據映射

如果此區塊已提供來源診斷，報告必須先判斷哪些來源可用：
- usable
- partially_usable
- missing
- extraction_failed
- irrelevant
- wrong_field
- truncated
- unknown

missing、extraction_failed、irrelevant、wrong_field、truncated 的來源不得被用來支撐圖片策略，只能放入「資料不足與後續補充建議」。

## Google Search 使用方式

Google Search 代表搜尋階段需求與購買前問題。

可以用於判斷：
- 買家為什麼搜尋這類產品
- 購買前正在確認什麼問題
- 搜尋階段的功能需求
- 常見市場語言
- 可放入主輔圖的購買前疑問
- Persona 分群線索

不可用於：
- 產品效果證明
- 真實使用後滿意度
- 實際負評原因
- 真實購買比例

如果 Google 搜尋意圖分析中有可計數資料，可作為 data chip 呈現。
若無法量化，只能標示為「定性支持」或「上游未提供明確頻次」。

## Reddit 使用方式

Reddit 代表社群真實使用討論與自然評論語言。

可以用於判斷：
- 真實使用情境
- 使用者實際痛點
- 使用後不滿
- 購買前猶豫
- 產品落差感
- 影響轉化的信任障礙
- 可直接轉成圖片文案的消費者語言

不可用於：
- 全市場普遍結論
- 絕對多數人的想法
- 產品一定有效或一定無效
- 單一留言不得寫成普遍承諾

如果 Reddit 分析中有真實使用痛點、購買阻礙、信任障礙、自然語言，必須優先用於「購買疑慮與信任缺口」與每張圖 Brief。

## YouTube Shorts Search 使用方式

YouTube Shorts Search 代表短影音內容搜尋需求、測評意圖、推薦方式與視覺包裝線索。

可以用於判斷：
- 消費者想看什麼測評 / 開箱 / 推薦內容
- 內容創作者如何包裝產品
- 哪些 Hook、標題、場景容易吸引停留
- 哪些 before / after、routine、Amazon finds、must-have 類型可作為內容形式參考
- 哪些使用情境適合轉成主輔圖或短影片腳本
- 哪些視覺場景可以作為圖片構圖參考

可以呈現：
- 影片數量
- Hook 類型
- 內容主題
- 視覺場景
- before / after 類型
- views_reference 或 views 作為內容熱度參考

不可呈現為：
- 消費者需求比例
- 產品效果證明
- 市場占比
- 產品功能驗證
- 真實購買原因

不得在 HTML 中顯示 YouTube Shorts thumbnail、影片縮圖、影片封面或 Shorts 截圖。
不得顯示 video_id、頻道 ID 或影片原始 URL。

## YouTube Comments 使用方式

YouTube Comments 代表影片觀眾留言反應、關鍵字提及、討論主題與高互動留言線索。

可以用於判斷：
- 本次留言樣本中觀眾最常討論什麼
- 哪些產品特點被反覆提及
- 哪些疑慮、抱怨、使用心得被留言提到
- 哪些關鍵字出現頻率最高
- 哪些高互動留言可以轉成內容 Hook
- 哪些留言是迷因、玩笑、灌水或與產品無關，應排除

可以呈現：
- 分析留言數
- 關鍵字頻率
- 留言主題
- 關鍵字提及次數
- 樣本內提及比例
- 高互動留言主題
- 情緒方向
- 無效或噪音留言排除結果

但所有比例只能寫成「本次留言樣本內」的統計。

正確寫法：
- 本次 YouTube 留言樣本中，X 則留言提到「_____」。
- 本次留言樣本內，該主題提及比例為 X%。
- 高互動留言集中在「_____」主題，可作為短影音 Hook 或輔圖疑慮提醒。
- 留言樣本與產品主題關聯不足，未納入設計決策。

禁止寫法：
- X% 消費者都在意
- 市場有 X% 需求
- YouTube 留言證明產品有效
- 高讚留言證明產品好用
- 單一留言代表全部使用者

## Persona 與內容策略使用方式

如果搜尋與社群內容分析中已判定可以生成 Persona，報告必須將 Persona 作為策略參考，但不得直接生成空泛人設。

Persona 只能用於判斷：
- 需求分群
- 使用場景
- 核心痛點
- 購買前疑慮
- 決策標準
- 信任門檻
- 文案語氣
- 圖片溝通順序
- 哪些圖應優先處理需求，哪些圖應負責解疑

不得根據 Persona 編造：
- 年齡
- 性別
- 收入
- 職業
- 居住地
- 家庭狀態
- 教育程度
- 消費能力
- 品牌偏好

除非上游明確提供，否則人口統計資訊一律不得出現在報告正文。

## 證據強度使用方式

如果搜尋與社群內容分析中提供證據強度，報告必須保留其證據強度判斷。

strong：
可作為核心結論與圖片策略主支撐。

medium：
可作為圖片策略輔助支撐，但需搭配其他資料來源。

weak：
只能作為內容角度或創意參考，不得單獨支撐核心策略。

insufficient：
不得納入核心結論，只能放入資料不足或後續補充建議。

如果來源狀態為 missing、irrelevant、wrong_field、extraction_failed、truncated，不得標示為 strong 或 medium。

## 搜尋與社群內容分析的 HTML 轉換規則

搜尋與社群內容分析不得被整段貼入報告。
必須轉換成主管與設計師能理解的策略語言。

1. 在「核心購買需求」卡片中：
   - 使用搜尋意圖、常見功能需求、跨來源需求訊號、Persona 中的核心需求。

2. 在「購買疑慮與信任缺口」卡片中：
   - 使用購買阻礙、信任障礙、留言主題、主要痛點、不信任觸發點。

3. 在「競品溝通現狀與差異化機會」卡片中:
   - 使用內容策略、跨 Persona 洞察、圖片策略啟示中可支撐圖片差異化的內容。

4. 在「宣稱風險與設計限制」卡片中：
   - 使用需避免的宣稱、不可推論內容、避免說法、claim risk。

5. 在「主輔圖溝通路徑總結」卡片中：
   - 使用跨來源需求訊號、內容策略、圖片優先議題、最高優先內容主題，總結整組圖片的說服順序。

6. 在「數據分析證據支撐」區塊中：
   - 分開呈現 Google Search、Reddit、YouTube Shorts Search、YouTube Comments。
   - 每一類來源都要標示可用性、主要訊號、數據或定性支持、限制。

# 七、產品主題一致性規則

如果搜尋與社群內容分析中的產品主題與產品核心資料不一致：
1. 不得把不一致的舊產品名稱、舊品類名稱或錯誤搜尋詞寫進報告正文。
2. 不得把錯誤品類的痛點、場景、關鍵字、Reddit 討論、YouTube Shorts Search 或 YouTube Comments 訊號套用到目前產品。
3. 只可在「資料不足與後續補充建議」中以自然語言寫：「搜尋與社群內容分析疑似與目前產品類目不一致，建議重新確認搜尋資料來源。」
4. 不要列出錯誤品類名稱、錯誤影片名稱、video_id 或無關迷因名稱。
5. 若後續資料已補充為正確產品類目，報告應直接使用正確資料，不要寫「已更新」「已修正」「已替換」這類修改紀錄式語氣。

# 八、數據支持規則

你必須盡可能從搜尋與社群內容分析、評論與競品數據分析、圖片策略架構中提取可審核的數據支持。

count、ratio、percentage、views、video_count、review_count、rating、rank、market_share、留言樣本數、留言提及次數、留言樣本內提及比例、可逐條計數的清單。

如果沒有明確數字，請使用：
- 上游未提供明確頻次
- 僅能判斷為定性支持
- 僅能判斷為多來源重複出現
- 無法計算占比
- 需補充統計口徑

不得自行假設「最多」「最高」「第一」。
如果無法量化，請標示為「定性支持」。

數據支持小標籤可使用以下 icon 類型：
- 📊 市場 / BSR / 排名數據
- 💬 評論 / Review / YouTube 留言提及
- 🔍 搜尋意圖 / Google Search
- 🧩 競品賣點重複
- ⚠️ 合規 / Claim 風險
- 🧪 定性支持
- 🔗 來源連結
- ▶️ YouTube Shorts Search / 短影音內容訊號
- 👥 Reddit / 社群討論訊號

HTML 中必須建立以下 data chip 組件：
.data-chip
.data-chip-icon
.data-chip-label
.data-chip-value
.data-chip-source
.data-chip-qualitative
.data-chip-warning

data chip 呈現邏輯：
1. 有明確數字：顯示 icon + 指標名稱 + 數值 + 自然資料來源名稱
2. 沒有明確數字但有多來源重複：顯示 icon + 定性支持 + 自然資料來源名稱
3. 沒有任何支持：顯示 ⚠️ + 資料不足 + 需補充

YouTube Shorts Search 與 YouTube Comments 必須分開處理。

YouTube Shorts Search 可以呈現：
- 影片數量
- 內容主題
- Hook 類型
- 視覺場景
- before / after 類型
- views 作為內容熱度參考

YouTube Shorts Search 不可呈現為：
- 消費者需求比例
- 產品效果證明
- 市場占比
- 產品功能驗證

YouTube Comments 可以呈現：
- 分析留言數
- 關鍵字頻率
- 留言主題
- 提及次數
- 樣本內提及比例
- 高互動留言主題
- 情緒方向

YouTube Comments 不可呈現為：
- 全市場需求比例
- 產品效果證明
- 消費者普遍結論
- 市場占比

- detailUrl
- source_url
- sourceUrl
- url
- asin_url
- amazon_url
- product_link
- productLink
- asin

     「圖片 1｜主圖：建立產品識別與第一眼信任」

   - 說明這張圖在整組主輔圖裡負責說服哪一件事

     a. 這張圖為什麼出現在這個階段
     b. 它承接上一張什麼內容
     c. 它推進下一張什麼內容

   - 不要用問句式標題

   - 合併呈現資料事實與策略解釋
   - 不得寫成資料來源摘要

5. 具體設計執行
   - 說明這張圖具體要怎麼做
   - 包含畫面構圖、產品位置、文案方向、icon / callout / 場景元素

   - 如果沒有 layout 圖片 URL，必須用 HTML + CSS 生成簡易 wireframe 示意圖，不得留空

   - 提供可放入圖片中的短文案

   - 說明可借鑑元素、不可照搬內容、我方差異化處理、產品外觀保真要求

9. 宣稱風險與數據支持
   - 說明此圖的風險點與數據支持
   - 若缺數據，必須標示定性支持或資料不足

10. 與 Hero 一句話策略總結的關聯
   - 說明此圖如何支撐 Hero 中的單一核心主軸

禁止出現以下段落標題：
- 為什麼這張圖放在第一張
- 為什麼這張圖放在第二張
- 客觀觀察
- 圖片行動
