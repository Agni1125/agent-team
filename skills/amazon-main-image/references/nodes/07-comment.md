# 最終輸出規則

只輸出完整 HTML。

不要輸出 Markdown。

<!DOCTYPE html>

- <!DOCTYPE html>
- <html lang="zh-Hant">
- <head>

- <meta name="viewport" content="width=device-width, initial-scale=1.0">
- <title>
- <style>
- <body>

- 外部 CSS

- Tailwind
- Bootstrap
- Vue

## 2. Executive Summary / 總結論先行

建立一張白色大卡片。

錯誤方式：
先列一堆數字，再讓讀者自己理解。

正確方式：
先說這代表什麼，再用數據或資料依據說明為什麼。

此區下方建立 4 個流程卡片，桌面 4 欄，手機 1 欄：

1. 痛點切入
2. 功能證明

- 階段名稱

## 3. 核心洞察深色區

建立一個深色橫向區塊。

- 洞察標題

- 最明確的消費者痛點

- 評論中最常出現的購買疑慮
- 外觀 / 質感 / 場景美感相關機會
- 圖片與影片最應該表現的核心賣點

如果資料不足，請在卡片中寫：

資料不足，暫不建議下結論。

## 4. 消費者決策問題區

建立 2x2 卡片區。

每張卡代表一個消費者下單前問題。

問題可根據資料自動生成，例如：

- 這個產品真的能解決我的問題嗎？
- 為什麼它比競品更值得買？
- 使用起來會不會麻煩？
- 外觀、材質、質感是否符合期待？
- 適合哪些使用場景？
- 是否存在常見負評風險？

每張卡包含：

- 消費者問題
- 資料依據
- 分析解讀
- 對應圖片 / A+ / Listing 表達方向

不要只寫問題，要把問題轉成內容策略。

## 5. KPI 與市場資料視覺化區

建立一個資料視覺化區塊。

### 5.1 KPI 數字卡

根據資料可用性產出 4 到 8 張 KPI 卡。

可包含：

- Review 數

- Top 品牌
- Top Seller
- 月銷量

規則：

如果資料有明確數字，顯示數字。
如果資料沒有明確數字，顯示「資料不足」。
不要編造評論數量、銷量、星級、價格、市佔或排名。

### 5.2 水平條圖

如果資料中有足夠資訊，使用純 CSS 做水平條圖。

可呈現：

- 痛點強度
- 賣點提及度
- 價格帶分布
- 評分分布
- 品牌集中度
- Seller 集中度
- 圖片策略優先級
- 視覺評估分數

如果沒有足夠數據，不要硬做百分比。
可以改為「資料充足度條」或顯示「資料不足，不建議生成圖表」。

### 5.3 分析表格

建立一個乾淨表格。

表格欄位建議：

- 資料主題
- 核心結論
- 資料支撐
- 分析解讀
- 可轉化方向

表格要求：

- 不要塞太多長文字
- 長文字請摘要
- 表格外層需可橫向滾動
- 每列都要有資料依據
- 最多優先呈現 5 到 10 列
- 如果資料很多，標示「節錄重點」

## 12. 圖片生成任務拆解區

這是本頁最重要的核心區塊。

如果資料中有圖片策略、主圖、輔圖、A+ 圖、圖片生成方向，請建立 5 到 7 張圖片任務卡。

每張任務卡包含：

- 任務編號，例如：主圖、輔圖 1、輔圖 2、A+ 圖 1、Scene 1
- 任務標題
- 任務目的
- 對應痛點
- 這張圖要回答的消費者問題
- 為什麼要放這張
- 資料支撐
- 建議畫面描述
- 建議英文 Overlay
- 注意事項
- 風險提醒
- 優先級狀態標籤

優先級標籤可用：

- 高優先
- 中優先
- 可延後
- 需重做
- 可進影片

每張任務卡下方建立 3 欄圖片區：

1. 參考圖
2. 生成圖
3. 待優化圖

如果沒有圖，顯示 placeholder：

- Reference Image
- Generated Image
- Pending Optimization

任務卡視覺要求：

- 像專案管理看板
- 不是純文字段落
- 不是普通表格
- 每張卡右上角有狀態標籤
- 卡片內資訊要有小標題分區
- 不要讓單張卡變成大段文字牆

圖片順序建議遵守：

1. 先解決最直接痛點
2. 再證明產品為什麼有效
3. 再說明使用可行性
4. 再處理舒適、安全、材質、外觀等疑慮
5. 最後補充差異化與成交理由
