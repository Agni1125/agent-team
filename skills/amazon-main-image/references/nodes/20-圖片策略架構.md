一、核心理解：Search / SerpAPI 節點的真正用途

Search / SerpAPI 節點不是普通市場資料節點，而是「需求反推節點」。

當使用者搜尋某個產品關鍵字時，代表他已經有某個待解決的問題、使用需求、購買疑慮、功能期待或場景需求。

因此，搜尋詞、Google 修正詞、相關搜尋、相關問題、自然搜尋結果、圖片結果與影片結果，都應被視為消費者在搜尋階段暴露出的需求訊號。

你必須把 {{Product_search}} 視為：

消費者搜尋需求入口

消費者痛點前置信號

消費者購買前疑慮來源

市場常用產品語言來源

圖片與影片表達方向參考

但你也必須注意：{{Product_search}} 只能反映「消費者在找什麼、在怕什麼、在期待什麼」。它不能直接證明我方產品具備某個功能，也不能創造 product_info 沒有的產品能力。

所有產品宣稱必須回到 {{product_info}} 驗證。

二、任務背景與成交邏輯

Amazon 消費者通常是帶著明確需求進入搜尋頁。

當他點進商品頁後，不會慢慢研究所有資訊，而是會在極短時間內快速判斷：

這個產品能不能幫我解決問題？

它真的有用嗎？

我買回來能不能順利使用？

長時間使用起來是否安心、舒服、可靠？

為什麼我要選你，而不是選其他競品？

因此，你設計圖片策略時，必須嚴格依照以下成交邏輯來排序：

結果承諾：先告訴顧客這個產品能幫他解決什麼問題。

原理證明：再說明它為什麼真的有用。

使用可行：再解除「買回來能不能裝、能不能用、會不會買錯」的疑慮。

體驗安心：再補足長時間使用的舒適感、材質信任感、品質安全感或日常維護疑慮。

差異成交：最後再做比較、差異化或價值總結，推動成交。

你規劃圖片時，必須嚴格遵守這個邏輯，不可顛倒。
